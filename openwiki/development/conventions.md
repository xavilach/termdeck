# Development conventions and review agents

The rules below come from `CLAUDE.md` (project instructions) and `REQUIREMENTS.md`; the
`.claude/agents/` folder defines reviewer and helper agents that check changes against them.

## Toolchain

Python ≥ 3.11, managed with `uv` (`uv sync --all-extras`, `uv run pytest -q`). The build
backend is `uv_build`; the console script is `termdeck = "termdeck.cli:main"`. Development
happens on Linux/WSL2, but Windows is the main target (COM ports, console mode, WebView2), so
Windows behaviour must be reasoned about from the code.

## Rules

1. **Every profile option is declared once** with `option()` in `profiles.py`. UIs build
   forms from `describe_options()` and never hand-code a form field. See
   [Profiles and the option registry](../core/profiles-and-options.md).
2. **Advanced by default**: mark an option `advanced=True` unless most users need it, and
   restrict it with `kinds=` when it applies only to SSH or serial. Forms show only the selected
   type's options.
3. **Shared behaviour belongs in the core** (e.g. `TerminalSession`, `SessionController`), not
   in a UI. See [Architecture overview](../architecture/overview.md).
4. **Remote or user text never goes into Textual markup or `innerHTML` unescaped.** The core
   helpers `printable`, `clean_title` and `clean_paste` exist for this; see the
   [Security model](../security/model.md).
5. **Tests use no network and no hardware**: a local asyncssh server and pyserial's `loop://`
   stand in. **Every fixed bug gets a test.** See [Test suite](../testing/test-suite.md).
6. **Requests from the owner go in `REQUIREMENTS.md`.**

## Requirements and scope (`REQUIREMENTS.md`)

Features: SSH, serial consoles, saved profiles, local/remote/dynamic forwarding, SFTP,
Windows-first cross-platform support, recognizing a serial adapter after its COM number changes,
local line editing, and every PuTTY SSH/serial option unless explicitly out of scope.
Interfaces: one core with CLI, TUI, local web UI and desktop GUI; `termdeck` opens the TUI and
`termdeck connect` works like `ssh`; rarer options behind an "Advanced" switch; only the selected
profile type's options; a professional desktop-tool look.

Out of scope unless requested: Telnet, Rlogin, Raw and SUPDUP connections; PuTTYgen-style key
generation and a Pageant-style agent.

## Review agents (`.claude/agents/`)

Reviewers that apply to a change run in parallel; findings are fixed, then the tests run again.
All reviewers are read-only and report findings.

| Agent | When |
|---|---|
| `conventions-reviewer` | after every change (checks the rules above) |
| `test-writer` | after a feature or fix; edits only `tests/` |
| `security-reviewer` | changes to auth, host keys, the web server, SFTP, forwarding, logs, serial control lines or secrets |
| `windows-reviewer` | changes to serial, the console, paths and permissions, the GUI, packaging or asyncio |
| `features-reviewer` | after adding features or options, and before a release (checks against PuTTY and `REQUIREMENTS.md`) |
| `interface-reviewer` | after UI changes (CLI, TUI, web, desktop) |
| `architecture-reviewer` | before large features, after big refactors, or periodically |
| `putty-reference` | answers how PuTTY does something, from a PuTTY source archive, instead of reading C code in the main session |

termdeck does not copy PuTTY code; PuTTY is a behavioural reference (option set, bell
overload, Features panel, proxy diagnostics, host-key pinning).
